1. Project Overview

This system simulates the backend warehouse infrastructure of a large e-commerce company like Amazon or Flipkart. It manages the complete lifecycle of products — from incoming shipments to dispatch — across a multi-rack warehouse with 10 storage sections.

The project is implemented in two forms: a Java console application and a browser-based web dashboard deployed live on Netlify.

9. Viva Preparation — Q & A

Q: Why ArrayList for inventory instead of Array?

Inventory size changes dynamically as products are added/removed. ArrayList handles resizing automatically. Arrays have fixed size and require manual management.

Q: Why Vector for shipment log instead of ArrayList?

Vector is synchronized (thread-safe). Multiple employees may access the shipment log simultaneously. Vector prevents data corruption in concurrent access scenarios.

Q: Why Queue for dispatch?

Shipments must be processed in the order they were requested — first queued, first dispatched. Queue (FIFO) models this real-world behavior perfectly using LinkedList implementation.

Q: Why custom exceptions?

Generic exceptions don't convey domain meaning. LowStockException immediately tells any developer exactly what went wrong — essential in professional, maintainable software.

Q: Why packages?

Packages organize large applications into logical modules. ecommerce.products contains product logic; ecommerce.shipment contains shipment logic. This is standard in industry (Maven, Spring Boot).

Q: Explain Smart Rack Allocation.

The Category enum stores the rack assignment (e.g., ELECTRONICS → Rack A). When a product is created, StorageManager.allocateStorage() calls getRackForCategory(product.getCategory()) to find the correct Rack object automatically — no manual input needed.
